# Универсальное руководство по переносу данных со старого диска (NTFS) в хранилище TrueNAS

Данная инструкция описывает безопасный и высокоскоростной перенос файлов с внешнего жёсткого диска (подключённого через USB-переходник к серверу Proxmox) в любой датасет TrueNAS через виртуальную машину Ubuntu Server (`VM 101`).

---

## Шаг 1. Проброс USB-диска в Ubuntu (на хосте Proxmox)

1. Откройте веб-интерфейс **Proxmox VE** (`https://192.168.89.201:8006`).
2. Перейдите в `101 (ubuntu-docker)` -> **Hardware** -> **Add** -> **USB Device**.
3. Выберите **Use USB Vendor/Device ID** (или *Use USB Port*), укажите ваш внешний жёсткий диск из списка (обычно отображается как контроллер USB-SATA, например *JMicron*, *ASMedia* или *Realtek*) и нажмите **Add**.
4. Убедитесь, что галочка **USB3** отмечена (если адаптер поддерживает USB 3.0). Диск пробросится в виртуальную машину без её перезагрузки.

---

## Шаг 2. Монтирование старого диска в Ubuntu через быстрый драйвер `ntfs3`

Подключитесь к Ubuntu по SSH (`ssh имя_пользователя@192.168.89.203`) и выполните следующие действия:

1. **Определите имя раздела с данными и убедитесь, что USB работает на скорости 3.0:**
   ```bash
   lsblk -f
   lsusb -t
   ```
   * В выводе `lsblk -f` найдите подключённый USB-диск нужного объёма (например, `sdb` или `sdc`) и его основной раздел с файловой системой `ntfs` (обычно `sdb1` или `sdb2`; первый мелкий раздел на 16–100 МБ является системным разделом Windows).
   * В выводе `lsusb -t` убедитесь, что устройство подключено на скорости **`5000M`** (USB 3.0), а не `480M` или `12M`.

2. **Примонтируйте диск в режиме «только чтение» (`ro`) через встроенный в ядро драйвер `ntfs3`:**
   > **Важно:** не используйте устаревший драйвер `ntfs-3g` (`fuseblk`), так как в виртуальной машине он работает через пространство пользователя и снижает скорость чтения до 2–5 МБ/с. В Ubuntu 24.04 используется быстрый ядерный драйвер **`ntfs3`**.
   ```bash
   sudo mkdir -p /mnt/legacy_hdd
   sudo mount -t ntfs3 -o ro,uid=1000,gid=1000 /dev/<РАЗДЕЛ> /mnt/legacy_hdd
   ```
   *(Замените `<РАЗДЕЛ>` на имя вашего раздела из вывода `lsblk`, например `sdc2`)*.

3. **Проверьте тип драйвера и доступность файлов:**
   ```bash
   mount | grep /mnt/legacy_hdd
   ls -la /mnt/legacy_hdd
   ```
   В выводе `mount` должно быть указано **`type ntfs3`**.

## Шаг 3. Подготовка целевого датасета (включение записи и ускорение ZFS)

> **Примечание:** Выполняйте пункты 1 и 2 только в том случае, если целевой датасет по умолчанию смонтирован в режиме «только чтение» (`Read-Only`). Если запись в целевую папку уже разрешена, сразу переходите к пункту 3.

1. **В веб-интерфейсе TrueNAS (`http://192.168.89.202`):**
   * **Разрешите запись по NFS:** перейдите в **Shares** -> **UNIX (NFS) Shares** -> значок редактирования напротив пути к вашему датасету (`/mnt/<ПУЛ>/<ПУТЬ_К_ДАТАСЕТУ>`) -> **Advanced Options** -> снимите галочку **Read Only** -> **Save**.
   * **Перезапустите NFS:** перейдите в **System** -> **Services**, найдите службу **NFS** и нажмите кнопку перезапуска (**Restart**).
   * *(Опционально, если копируете тысячи мелких фото или документов)* **Ускорьте запись в ZFS на время переноса:** перейдите в **Datasets** -> выберите целевой датасет -> **Edit** -> переключите параметр **Sync** со `Standard` на **`Disabled`** -> **Save**. *(После завершения переноса обязательно верните значение `Standard`)*.

2. **В терминале Ubuntu (`192.168.89.203`):**
   Остановите юнит авто-монтирования для целевой шары и смонтируйте её вручную с флагом `rw` (имя юнита соответствует пути монтирования, где слэши `/` заменены на дефисы `-`):
   ```bash
   sudo systemctl stop <ПУТЬ-ТОЧКИ-МОНТИРОВАНИЯ>.automount
   sudo umount -l /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>
   sudo mount -t nfs -o rw,defaults 192.168.89.202:/mnt/<ПУЛ>/<ПУТЬ_К_ДАТАСЕТУ> /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>
   ```
   *(Пример: для `/mnt/nas/media/collection` имя юнита будет `mnt-nas-media-collection.automount`)*.

3. **Создайте целевой каталог при необходимости:**
   ```bash
   mkdir -p /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>
   ```
   *(Учитывайте регистр букв в именах каталогов: в Linux имена с заглавной и строчной буквы считаются разными директориями)*.

## Шаг 4. Копирование файлов с правильными правами доступа

Файловая система NTFS не хранит права доступа Linux, поэтому все файлы на старом диске отображаются с правами `777`. Чтобы не перенести права `777` в хранилище, используйте `rsync` с флагом `--no-perms` и явным назначением прав (`755` для папок и `644` для файлов).

1. **Запустите фоновую сессию `tmux` (чтобы копирование не прервалось при закрытии SSH):**
   ```bash
   tmux new -s copy
   ```
   *(Вернуться в сессию после переподключения по SSH можно командой `tmux attach -t copy`)*.

2. **Запустите копирование выбранной папки (или всего диска):**
   ```bash
   rsync -ah --info=name1,progress2 --no-perms --chmod=Du=rwx,Dgo=rx,Fu=rw,Fgo=r /mnt/legacy_hdd/<ИСХОДНАЯ_ПАПКА>/ /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/
   ```
   *(Чтобы скопировать всё содержимое старого диска целиком, укажите в качестве источника `/mnt/legacy_hdd/`)*.
   
   **Что делают параметры команды:**
   * `--info=name1,progress2` — построчно выводит имена копируемых файлов, а в самой нижней строке терминала закрепляет общий прогресс в процентах, текущую скорость (МБ/с) и оставшееся время (`ETA`).
   * `--no-perms` — отключает копирование прав `777` с NTFS-раздела.
   * `--chmod=Du=rwx,Dgo=rx,Fu=rw,Fgo=r` — задаёт права `755` для всех новых папок (`D`) и `644` для всех файлов (`F`).

3. **Если часть файлов уже была скопирована ранее с правами `777`**, исправьте их права следующими командами:
   ```bash
   find /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА> -type d -exec chmod 755 {} +
   find /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА> -type f -exec chmod 644 {} +
   ```

## Шаг 5. Проверка целостности скопированных данных

Перед тем как отключить старый диск, убедитесь, что все файлы перенеслись без потерь. Обычное сравнение по датам (`-a`) не подходит, так как при переносе с NTFS на NFS даты изменения и метаданные отличаются. Используйте режим пробного запуска (`-n`) без учёта метаданных (`-r`):

1. **Быстрая проверка по именам и размеру файлов (рекомендуется):**
   ```bash
   rsync -rni --size-only --delete /mnt/legacy_hdd/<ИСХОДНАЯ_ПАПКА>/ /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/
   ```
   * **Пустой вывод** означает, что все файлы на месте, их размеры совпадают и лишних файлов нет.
   * Если в выводе появятся строки (например, `>f+++++++++` — пропущенный файл или `>f.s.......` — не совпадает размер), повторно запустите команду копирования из Шага 4.

2. **Строгая побайтовая проверка по контрольным суммам (опционально):**
   Если нужно на 100% исключить повреждение байтов внутри файлов при совпадении их размеров (команда читает все файлы целиком, поэтому занимает много времени):
   ```bash
   rsync -rnic --delete /mnt/legacy_hdd/<ИСХОДНАЯ_ПАПКА>/ /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/
   ```
   * **Пустой вывод** гарантирует полную побайтовую идентичность копии и оригинала.
   * Строки вида `>fc........` укажут на файлы, у которых отличается контрольная сумма.

---

## Шаг 6. Завершение работы, возврат защиты и отключение диска

После завершения переноса и проверки всех данных отключите внешний диск и при необходимости верните систему в штатный защищённый режим:

1. **Отмонтируйте старый диск в Ubuntu и удалите проброс:**
   ```bash
   sudo umount /mnt/legacy_hdd
   ```
   В веб-интерфейсе **Proxmox** (`101` -> **Hardware**) выделите добавленный ранее **USB Device**, нажмите **Remove** и физически отключите диск от сервера.

2. **Если на Шаге 3 вы меняли настройки датасета или NFS в TrueNAS (`http://192.168.89.202`):**
   * Если отключали синхронную запись: перейдите в **Datasets** -> ваш датасет -> **Edit** -> верните параметр **Sync** в значение **`Standard`** -> **Save**.
   * Если датасет должен быть защищён от записи: перейдите в **Shares** -> **UNIX (NFS) Shares** -> редактирование пути вашего датасета -> **Advanced Options** -> поставьте галочку **Read Only** -> **Save**.
   * Перейдите в **System** -> **Services** и перезапустите службу **NFS** (**Restart**).

3. **Если на Шаге 3 вы переводили монтирование в режим `rw` в Ubuntu:**
   ```bash
   sudo umount -l /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>
   sudo systemctl daemon-reload
   sudo systemctl start <ПУТЬ-ТОЧКИ-МОНТИРОВАНИЯ>.automount
   ```

4. **При переносе медиафайлов обновите библиотеки в соответствующих сервисах** (например, в **Jellyfin** по адресу `http://192.168.89.204:8096`: **Панель управления** -> **Библиотеки** -> **Сканировать все библиотеки**).
