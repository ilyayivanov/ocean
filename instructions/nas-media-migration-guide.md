# Руководство по переносу медиатеки со старого диска (Windows NTFS) в хранилище TrueNAS

Данная инструкция описывает безопасный перенос файлов с внешнего жёсткого диска (подключённого через USB-переходник к серверу Proxmox) в защищённый датасет `collection` через виртуальную машину Ubuntu Server (`VM 101`).

---

## Шаг 1. Проброс USB-диска в Ubuntu (на хосте Proxmox)

1. Откройте веб-интерфейс **Proxmox VE** (`https://192.168.89.201:8006`).
2. Перейдите в `101 (ubuntu-docker)` -> **Hardware** -> **Add** -> **USB Device**.
3. Выберите **Use USB Vendor/Device ID** (или *Use USB Port*), укажите ваш внешний жёсткий диск из списка (обычно отображается как контроллер USB-SATA, например *JMicron*, *ASMedia* или *Realtek*) и нажмите **Add**.
4. Убедитесь, что галочка **USB3** отмечена (если адаптер поддерживает USB 3.0). Диск пробросится в виртуальную машину без её перезагрузки.

---

## Шаг 2. Монтирование старого диска в Ubuntu

Подключитесь к Ubuntu по SSH (`ssh имя_пользователя@192.168.89.203`) и выполните следующие действия:

1. **Установите драйвер `ntfs-3g` (если не установлен):**
   ```bash
   sudo apt update && sudo apt install -y ntfs-3g
   ```

2. **Определите имя раздела с данными:**
   ```bash
   lsblk -f
   ```
   Найдите подключённый USB-диск нужного объёма (например, `sdb`) и его основной раздел с файловой системой `ntfs` (обычно `sdb1` или `sdb2`; первый мелкий раздел на 16–100 МБ является системным разделом Windows).

3. **Примонтируйте диск в режиме «только чтение» (`ro`) для защиты исходных данных:**
   ```bash
   sudo mkdir -p /mnt/old_hdd
   sudo mount -t ntfs-3g -o ro,uid=1000,gid=1000 /dev/sdX1 /mnt/old_hdd
   ```
   *(Замените `sdX1` на имя вашего раздела из вывода `lsblk`, например `sdb1`)*.

4. **Убедитесь, что файлы доступны:**
   ```bash
   ls -la /mnt/old_hdd
   ```

---

## Шаг 3. Временное включение записи в датасет `collection`

По умолчанию датасет `collection` защищён от записи на уровне настроек NFS в TrueNAS и опцией `ro` в `/etc/fstab` Ubuntu (при этом юнит `systemd.automount` не позволяет просто так выполнить `remount,rw` без его остановки). Чтобы разрешить запись на время переноса:

1. **В веб-интерфейсе TrueNAS (`http://192.168.89.202`):**
   * Перейдите в **Shares** -> **UNIX (NFS) Shares**.
   * Нажмите значок редактирования напротив шары `/mnt/tank/media/collection`.
   * Откройте **Advanced Options**, снимите галочку **Read Only** и нажмите **Save**.
   * Перейдите в **System** -> **Services**, найдите службу **NFS** и нажмите кнопку перезапуска (**Restart**), чтобы сервер гарантированно применил новые права экспорта.

2. **В терминале Ubuntu (`192.168.89.203`):**
   Остановите юнит авто-монтирования и смонтируйте шару вручную с флагом `rw`:
   ```bash
   sudo systemctl stop mnt-nas-media-collection.automount
   sudo umount -l /mnt/nas/media/collection
   sudo mount -t nfs -o rw,defaults 192.168.89.202:/mnt/tank/media/collection /mnt/nas/media/collection
   ```

3. **Проверьте возможность создания каталогов:**
   ```bash
   mkdir -p /mnt/nas/media/collection/Music/legacy_collection
   ```
   *(Учитывайте регистр букв в именах каталогов: в Linux `Music` и `music` — это разные директории).*

## Шаг 4. Копирование файлов с правильными правами доступа

Файловая система NTFS не хранит права доступа Linux, поэтому драйвер `ntfs-3g` отображает все файлы на старом диске с правами `777`. Чтобы не перенести права `777` в хранилище, используйте `rsync` с флагом `--no-perms` и явным назначением прав (`755` для папок и `644` для файлов).

1. **Запустите фоновую сессию `tmux` (чтобы копирование не прервалось при закрытии SSH):**
   ```bash
   tmux new -s copy
   ```
   *(Вернуться в сессию после переподключения по SSH можно командой `tmux attach -t copy`)*.

2. **Запустите копирование выбранной папки:**
   ```bash
   rsync -ah --info=name1,progress2 --no-perms --chmod=Du=rwx,Dgo=rx,Fu=rw,Fgo=r /mnt/old_hdd/Путь_к_папке/ /mnt/nas/media/collection/Целевая_папка/
   ```
   **Что делают параметры команды:**
   * `--info=name1,progress2` — построчно выводит имена копируемых файлов, а в самой нижней строке терминала закрепляет общий прогресс в процентах, текущую скорость (МБ/с) и оставшееся время (`ETA`).
   * `--no-perms` — отключает копирование прав `777` с NTFS-раздела.
   * `--chmod=Du=rwx,Dgo=rx,Fu=rw,Fgo=r` — задаёт права `755` для всех новых папок (`D`) и `644` для всех файлов (`F`).

3. **Если часть файлов уже была скопирована ранее с правами `777`**, исправьте их права следующими командами:
   ```bash
   find /mnt/nas/media/collection/Целевая_папка -type d -exec chmod 755 {} +
   find /mnt/nas/media/collection/Целевая_папка -type f -exec chmod 644 {} +
   ```

---

## Шаг 5. Возврат защиты «только чтение» (`Read-Only`) и отключение диска

После завершения переноса всех данных верните систему в штатный защищённый режим:

1. **Отмонтируйте старый диск в Ubuntu и удалите проброс:**
   ```bash
   sudo umount /mnt/old_hdd
   ```
   В веб-интерфейсе **Proxmox** (`101` -> **Hardware**) выделите добавленный ранее **USB Device**, нажмите **Remove** и физически отключите диск от сервера.

2. **Верните защиту от записи в TrueNAS (`http://192.168.89.202`):**
   * Перейдите в **Shares** -> **UNIX (NFS) Shares** -> редактирование `/mnt/tank/media/collection` -> **Advanced Options**.
   * Поставьте галочку **Read Only** и нажмите **Save**.
   * Перейдите в **System** -> **Services** и перезапустите службу **NFS** (**Restart**).

3. **Верните штатное авто-монтирование в режиме `ro` в Ubuntu:**
   ```bash
   sudo umount -l /mnt/nas/media/collection
   sudo systemctl start mnt-nas-media-collection.automount
   ```

4. **Обновите медиатеку в Jellyfin (`http://192.168.89.204:8096`):**
   Перейдите в **Панель управления** -> **Библиотеки** и нажмите **Сканировать все библиотеки**.
