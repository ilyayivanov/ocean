# Универсальное руководство по переносу данных со старого диска (NTFS) в хранилище TrueNAS

Данная инструкция описывает безопасный и высокоскоростной перенос файлов с внешнего жёсткого диска (подключённого через USB-переходник к серверу Proxmox) в любой датасет TrueNAS через виртуальную машину Ubuntu Server (`VM 101`).

---

## Шаг 1. Проброс USB-диска в Ubuntu (на хосте Proxmox)

1. Откройте веб-интерфейс **Proxmox VE** (`https://192.168.89.201:8006`).
2. Перейдите в `101 (ubuntu-docker)` -> **Hardware** -> **Add** -> **USB Device**.
3. Выберите **Use USB Vendor/Device ID** (или *Use USB Port*), укажите ваш внешний жёсткий диск из списка (обычно отображается как контроллер USB-SATA, например *JMicron*, *ASMedia* или *Realtek*) и нажмите **Add**.
4. Убедитесь, что галочка **USB3** отмечена (если адаптер поддерживает USB 3.0). Диск пробросится в виртуальную машину без её перезагрузки.

---

## Шаг 2. Определение диска и монтирование в Ubuntu через быстрый драйвер `ntfs3`

Подключитесь к Ubuntu по SSH (`ssh имя_пользователя@192.168.89.203`) и выполните следующие действия:

1. **Определите имя раздела с данными и убедитесь, что USB работает на скорости 3.0:**
   ```bash
   lsblk -f
   lsusb -t
   ```
   * В выводе `lsblk -f` найдите подключённый USB-диск нужного объёма (например, `sdb` или `sdc`) и его основной раздел с файловой системой `ntfs` (обычно `sdb1` или `sdb2`; первый мелкий раздел на 16–100 МБ является системным разделом Windows).
   * В выводе `lsusb -t` убедитесь, что устройство подключено на скорости **`5000M`** (USB 3.0), а не `480M` или `12M`.

> **Выбор стратегии переноса:**
> * Если на диске лежат **обычные файлы** (фото, видео, документы) — примонтируйте раздел (пункт 2 ниже) и используйте **Вариант А** или **Вариант Б** из Шага 4.
> * Если на диске **сотни тысяч/миллионы мелких файлов** (артефакты сборки `target`, `node_modules`, git-индексы, кэши), из-за чего чтение падает до КБ/с — **не монтируйте раздел** (или отмонтируйте его) и сразу переходите к **Варианту В** (образ только занятых блоков через `ntfsclone` — оптимально, если диск заполнен не полностью) или **Варианту Г** (полный посекторный образ через `ddrescue` — если нужно скопировать весь диск целиком или есть подозрения на битые сектора) в Шаге 4.

2. **Примонтируйте диск в режиме «только чтение» (`ro`) через встроенный в ядро драйвер `ntfs3` (для пофайлового копирования):**
   > **Важно:** не используйте устаревший драйвер `ntfs-3g` (`fuseblk`), так как в виртуальной машине он работает через пространство пользователя и снижает скорость чтения до 2–5 МБ/с. В Ubuntu 24.04 используется быстрый ядерный драйвер **`ntfs3`**.
   ```bash
   sudo mkdir -p /mnt/legacy_hdd
   sudo mount -t ntfs3 -o ro,uid=1000,gid=1000 /dev/<РАЗДЕЛ> /mnt/legacy_hdd
   ```
   *(Замените `<РАЗДЕЛ>` на имя вашего раздела из вывода `lsblk`, например `sdc2`)*.

3. **Проверьте тип драйвера и доступность файлов:**
   ```bash
   mount | grep /mnt/legacy_hdd
   ls -la /mnt/legacy_hdd
   ```
   В выводе `mount` должно быть указано **`type ntfs3`**.

## Шаг 3. Подготовка целевого датасета (включение записи и ускорение ZFS)

> **Примечание:** Выполняйте пункты 1 и 2 только в том случае, если целевой датасет по умолчанию смонтирован в режиме «только чтение» (`Read-Only`). Если запись в целевую папку уже разрешена, сразу переходите к пункту 3.

1. **В веб-интерфейсе TrueNAS (`http://192.168.89.202`):**
   * **Разрешите запись по NFS:** перейдите в **Shares** -> **UNIX (NFS) Shares** -> значок редактирования напротив пути к вашему датасету (`/mnt/<ПУЛ>/<ПУТЬ_К_ДАТАСЕТУ>`) -> **Advanced Options** -> снимите галочку **Read Only** -> **Save**.
   * **Перезапустите NFS:** перейдите в **System** -> **Services**, найдите службу **NFS** и нажмите кнопку перезапуска (**Restart**).
   * *(Опционально, но настоятельно рекомендуется при переносе тысяч мелких файлов)* **Ускорьте запись в ZFS на время переноса:** перейдите в **Datasets** -> выберите целевой датасет -> **Edit** -> переключите параметр **Sync** со `Standard` на **`Disabled`** -> **Save**. *(После завершения переноса обязательно верните значение `Standard`)*.

2. **В терминале Ubuntu (`192.168.89.203`):**
   Остановите юнит авто-монтирования для целевой шары и смонтируйте её вручную с флагом `rw` (имя юнита соответствует пути монтирования, где слэши `/` заменены на дефисы `-`):
   ```bash
   sudo systemctl stop <ПУТЬ-ТОЧКИ-МОНТИРОВАНИЯ>.automount
   sudo umount -l /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>
   sudo mount -t nfs -o rw,defaults 192.168.89.202:/mnt/<ПУЛ>/<ПУТЬ_К_ДАТАСЕТУ> /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>
   ```
   *(Пример: для `/mnt/nas/media/collection` имя юнита будет `mnt-nas-media-collection.automount`)*.

3. **Создайте целевой каталог от имени владельца датасета (`backup_admin`):**
   ```bash
   sudo -v
   sudo -u backup_admin mkdir -p /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>
   ```
   *(Учитывайте регистр букв в именах каталогов: в Linux имена с заглавной и строчной буквы считаются разными директориями)*.

## Шаг 4. Копирование данных в TrueNAS

Файловая система NTFS не хранит права доступа Linux, поэтому все файлы на старом диске отображаются с правами `777`. Чтобы сохранить корректного владельца (`backup_admin`) и права доступа (`755` для папок и `644` для файлов), выберите один из четырёх способов ниже.

Перед запуском откройте фоновую сессию `tmux`, чтобы процесс не прервался при закрытии SSH:
```bash
tmux new -s copy
```
*(Вернуться в сессию после переподключения по SSH можно командой `tmux attach -t copy`)*.

### Вариант А. Пофайловый перенос через `rsync` (для крупных файлов и медиа)

Подходит для видео, фото, дистрибутивов и больших документов. Поддерживает докачку при обрыве.

1. **Запустите копирование выбранной папки (или всего диска):**
   ```bash
   sudo -v
   sudo -u backup_admin rsync -rhW --info=progress2 --no-perms --chmod=Du=rwx,Dgo=rx,Fu=rw,Fgo=r /mnt/legacy_hdd/<ИСХОДНАЯ_ПАПКА>/ /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/
   ```
   *(Чтобы скопировать всё содержимое старого диска целиком, укажите в качестве источника `/mnt/legacy_hdd/`)*.

   **Что делают параметры команды:**
   * `sudo -u backup_admin` — выполняет запись от имени владельца датасета.
   * `--info=progress2` — отображает общий прогресс, текущую скорость и оставшееся время (`ETA`) в одной строке, не замедляя терминал выводом каждого имени файла.
   * `-W` (`--whole-file`) — отключает алгоритм дельта-сравнения блоков (ускоряет локальное копирование).
   * `--no-perms` — отключает перенос прав `777` с NTFS-раздела.
   * `--chmod=Du=rwx,Dgo=rx,Fu=rw,Fgo=r` — задаёт права `755` для всех новых папок (`D`) и `644` для всех файлов (`F`).

2. **Если часть файлов уже была скопирована ранее с правами `777`**, исправьте их права:
   ```bash
   sudo -u backup_admin find /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА> -type d -exec chmod 755 {} +
   sudo -u backup_admin find /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА> -type f -exec chmod 644 {} +
   ```

### Вариант Б. Потоковый перенос через `tar` + `pv` (для большого числа мелких файлов)

Передаёт файлы в TrueNAS непрерывным потоком, исключая накладные расходы NFS на создание каждого мелкого файла по сети, а также позволяет отфильтровать кэши сборки.

1. **Установите утилиту `pv` (Pipe Viewer) для отображения прогресса:**
   ```bash
   sudo apt update && sudo apt install -y pv
   ```

2. **Запустите потоковое копирование всего диска с индикатором прогресса:**
   ```bash
   sudo -v
   tar -C /mnt/legacy_hdd      --exclude='System Volume Information'      --exclude='$RECYCLE.BIN'      --exclude='target'      --exclude='node_modules'      --exclude='.gradle'      --exclude='.m2'      -cf - . | pv -s $(df -B1 --output=used /mnt/legacy_hdd | tail -1) | sudo -u backup_admin tar -C /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА> --no-same-owner --no-same-permissions -xf -
   ```
   **Что делают параметры команды:**
   * `sudo -v` — кэширует пароль администратора перед запуском пайпа (таймаут 15 минут проверяется только в момент старта, запущенный процесс не прервётся).
   * `--exclude=...` — пропускает системные папки Windows и мусорные кэши сборки (при необходимости уберите или добавьте свои исключения).
   * `df -B1 --output=used /mnt/legacy_hdd | tail -1` — мгновенно берёт занятый объём диска в байтах из суперблока ФС для точного расчёта процентов и `ETA` в `pv`.
   * `--no-same-owner --no-same-permissions` — применяет стандартные права пользователя `backup_admin` (`755` для папок и `644` для файлов) вместо `777`.

### Вариант В. Снятие образа только занятых блоков NTFS через `ntfsclone` (быстрый образ без копирования пустого места)

Утилита `ntfsclone` читает карту занятых кластеров (`$Bitmap`) файловой системы NTFS и копирует исключительно используемые данные, полностью игнорируя свободное пространство. Это идеально, если на диске много мелких файлов, но сам раздел заполнен лишь частично.

1. **Убедитесь, что исходный раздел НЕ примонтирован:**
   ```bash
   sudo umount /mnt/legacy_hdd
   mount | grep <РАЗДЕЛ>
   ```
   *(Вывод `mount` должен быть пустым)*.

2. **Установите пакет `ntfs-3g` и разрешите `backup_admin` чтение физических дисков:**
   ```bash
   sudo apt update && sudo apt install -y ntfs-3g
   sudo usermod -aG disk backup_admin
   ```
   > **Примечание по безопасности:** Членство в группе `disk` предоставляет полный доступ (на чтение и запись) ко всем физическим накопителям в системе. Используйте этот метод только для доверенных служебных учётных записей.

3. **Запустите снятие образа одним из двух способов:**

   * **Способ 1. Специальный компактный образ (`.ntfs.img`) — минимальный объём при передаче:**
     Сохраняет только занятые блоки и карту их расположения в компактный файл:
     ```bash
     sudo -v
     sudo -u backup_admin ntfsclone --save-image -o /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/disk_<РАЗДЕЛ>.ntfs.img /dev/<РАЗДЕЛ>
     ```
     *Чтобы потом открыть файлы из такого образа*, его нужно развернуть в обычный RAW-образ (пустые области заполнятся нулями, которые ZFS сожмёт):
     ```bash
     sudo -u backup_admin ntfsclone --restore-image -o /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/disk_<РАЗДЕЛ>.img /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/disk_<РАЗДЕЛ>.ntfs.img
     ```

   * **Способ 2. Прямое создание монтируемого разреженного RAW-образа (`.img`):**
     Сразу создаёт обычный файл образа без промежуточной конвертации, пропуская чтение пустых блоков на HDD:
     ```bash
     sudo -v
     sudo -u backup_admin ntfsclone -o /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/disk_<РАЗДЕЛ>.img /dev/<РАЗДЕЛ>
     ```

   > **Примечание при ошибках ФС:** Если диск отключали некорректно, `ntfsclone` может попросить добавить флаг `--force` (если стоит флаг «грязного» тома Windows) или `--rescue` (для пропуска битых секторов).

4. **Как работать с готовым образом `.img` после отключения физического HDD:**
   ```bash
   sudo mkdir -p /mnt/img_view
   sudo mount -t ntfs3 -o ro,loop,uid=1000,gid=1000 /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/disk_<РАЗДЕЛ>.img /mnt/img_view
   ```
   *(После работы отмонтируйте образ командой `sudo umount /mnt/img_view`)*.

### Вариант Г. Полное посекторное снятие образа через `ddrescue` (максимальная линейная скорость и работа со сбойными дисками)

Если на диске лежат миллионы мелких `.class`, `.git` или кэш-файлов, которые нужно сохранить **без исключений**, или на диске есть сбойные сектора/ошибки файловой системы NTFS, головки механического HDD при пофайловом чтении тратят всё время на позиционирование (`seek`), из-за чего скорость падает до 20–50 КБ/с. Посекторное чтение заставляет диск отдавать данные линейно на максимальной скорости (80–120 МБ/с) по всему объёму раздела (включая незанятую область).

1. **Убедитесь, что исходный раздел НЕ примонтирован:**
   ```bash
   sudo umount /mnt/legacy_hdd
   mount | grep <РАЗДЕЛ>
   ```
   *(Вывод `mount` должен быть пустым)*.

2. **Установите утилиту `gddrescue` и разрешите `backup_admin` чтение физических дисков:**
   Чтобы запускать `ddrescue` напрямую от имени владельца датасета (`backup_admin`) и не сталкиваться с ограничением `root_squash` на NFS-шаре, добавьте пользователя в системную группу `disk`:
   ```bash
   sudo apt update && sudo apt install -y gddrescue
   sudo usermod -aG disk backup_admin
   ```
   > **Примечание по безопасности:** Членство в группе `disk` предоставляет полный доступ (на чтение и запись) ко всем физическим накопителям в системе. Используйте этот метод только для доверенных служебных учётных записей.

3. **Запустите снятие образа раздела в TrueNAS от имени `backup_admin`:**
   ```bash
   sudo -v
   sudo -u backup_admin ddrescue -d -r3 -b 4096 /dev/<РАЗДЕЛ> /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/disk_<РАЗДЕЛ>.img /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/disk_<РАЗДЕЛ>.map
   ```
   **Что делают параметры команды:**
   * `sudo -u backup_admin` — создаёт файлы образа и карты сразу от имени владельца датасета (права новой группы `disk` применятся автоматически при вызове `sudo -u`).
   * `-d` — прямой доступ к блочному устройству в обход кэша ядра (максимальная скорость и точная фиксация ошибок чтения).
   * `-r3` — до 3 попыток повторного чтения сбойных секторов при их обнаружении.
   * `-b 4096` — размер физического сектора 4 КБ.
   * `disk_<РАЗДЕЛ>.map` — файл карты (журнал). Если процесс прервётся, повторный запуск **этой же команды** продолжит снятие образа ровно с того места, где он остановился.

4. **Как работать с готовым образом `.img` после отключения физического HDD:**
   * Пустые блоки образа (если они заполнены нулями) ZFS автоматически сожмёт алгоритмом `lz4`/`zstd`.
   * Чтобы открыть образ как обычный диск и скопировать из него нужные файлы уже на высокой скорости ZFS-пула:
     ```bash
     sudo mkdir -p /mnt/img_view
     sudo mount -t ntfs3 -o ro,loop,uid=1000,gid=1000 /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/disk_<РАЗДЕЛ>.img /mnt/img_view
     ```
     *(После работы отмонтируйте образ командой `sudo umount /mnt/img_view`)*.

## Шаг 5. Проверка целостности скопированных данных

* **Если использовали Вариант В (`ntfsclone`):** убедитесь, что утилита завершила работу без ошибок и вывела сообщение `Syncing ...` / `100.00 percent completed`. При необходимости примонтируйте полученный `.img` в `/mnt/img_view` и проверьте наличие ключевых каталогов.
* **Если использовали Вариант Г (`ddrescue`):** целостность гарантируется файлом карты `.map` — убедитесь, что в конце работы `ddrescue` в строке `errsize` указано **`0 B`** (ноль сбойных байт).
* **Если использовали Вариант А или Б (пофайловый перенос):** перед отключением диска проверьте, что все файлы перенеслись без потерь. Обычное сравнение по датам (`-a`) не подходит, так как при переносе с NTFS на NFS даты изменения отличаются. Используйте режим пробного запуска (`-n`) без учёта метаданных (`-r`):

1. **Быстрая проверка по именам и размеру файлов (рекомендуется):**
   ```bash
   sudo -u backup_admin rsync -rni --size-only --delete      --exclude='System Volume Information'      --exclude='$RECYCLE.BIN'      /mnt/legacy_hdd/<ИСХОДНАЯ_ПАПКА>/ /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/
   ```
   *(Если при копировании через `tar` вы исключали папки вроде `target` или `node_modules`, добавьте их и сюда через `--exclude=...`)*.
   * **Пустой вывод** означает, что все файлы на месте, их размеры совпадают и лишних файлов нет.
   * Если в выводе появятся строки (например, `>f+++++++++` — пропущенный файл или `>f.s.......` — не совпадает размер), повторно запустите `rsync`.

2. **Строгая побайтовая проверка по контрольным суммам (опционально):**
   Если нужно на 100% исключить повреждение байтов внутри файлов при совпадении их размеров (команда читает все файлы целиком, поэтому занимает много времени):
   ```bash
   sudo -u backup_admin rsync -rnic --delete      --exclude='System Volume Information'      --exclude='$RECYCLE.BIN'      /mnt/legacy_hdd/<ИСХОДНАЯ_ПАПКА>/ /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>/<ЦЕЛЕВАЯ_ПАПКА>/
   ```
   * **Пустой вывод** гарантирует полную побайтовую идентичность копии и оригинала.
   * Строки вида `>fc........` укажут на файлы, у которых отличается контрольная сумма.

## Шаг 6. Завершение работы, возврат защиты и отключение диска

После завершения переноса и проверки всех данных отключите внешний диск и при необходимости верните систему в штатный защищённый режим:

1. **Отмонтируйте старый диск в Ubuntu (если он был примонтирован) и удалите проброс:**
   ```bash
   sudo umount /mnt/legacy_hdd
   ```
   В веб-интерфейсе **Proxmox** (`101` -> **Hardware**) выделите добавленный ранее **USB Device**, нажмите **Remove** и физически отключите диск от сервера.

2. **Если на Шаге 3 вы меняли настройки датасета или NFS в TrueNAS (`http://192.168.89.202`):**
   * Если отключали синхронную запись: перейдите в **Datasets** -> ваш датасет -> **Edit** -> верните параметр **Sync** в значение **`Standard`** -> **Save**.
   * Если датасет должен быть защищён от записи: перейдите в **Shares** -> **UNIX (NFS) Shares** -> редактирование пути вашего датасета -> **Advanced Options** -> поставьте галочку **Read Only** -> **Save**.
   * Перейдите в **System** -> **Services** и перезапустите службу **NFS** (**Restart**).

3. **Если на Шаге 3 вы переводили монтирование в режим `rw` в Ubuntu:**
   ```bash
   sudo umount -l /mnt/nas/<ПУТЬ_К_ДАТАСЕТУ>
   sudo systemctl daemon-reload
   sudo systemctl start <ПУТЬ-ТОЧКИ-МОНТИРОВАНИЯ>.automount
   ```

4. **При переносе медиафайлов обновите библиотеки в соответствующих сервисах** (например, в **Jellyfin** по адресу `http://192.168.89.204:8096`: **Панель управления** -> **Библиотеки** -> **Сканировать все библиотеки**).
